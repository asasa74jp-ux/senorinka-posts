# せのりんか公式LINE 自動返信Bot

SNS（Instagram / Threads / X）から来てくださった方を公式LINEで受け止め、
「月夜おみくじ」や無料診断へご案内する自動返信Botです。

**文面はすべてGoogleスプレッドシートで管理します。コードを触る必要はありません。**

## 1. 全体のしくみ

```
お客さまのLINE
   │「おみくじ」と送る
   ▼
LINE公式アカウント ──▶ Bot（Renderで動くプログラム）──▶ Googleスプレッドシート
                         返信を作って送り返す            文面・設定を読む
```

- Botは **5分おき** にスプレッドシートを読み直します。シートの文面を直すと、だいたい5分以内に反映されます。
- どのキーワードにも当てはまらないメッセージには、**Botは返信しません**。
  LINE公式アカウントのチャット画面から、ご本人が1対1でお返事できます。
- 費用：お客さまのメッセージへの返信（応答メッセージ）は、LINEの月の配信通数に**数えられません**。
  Render・Googleも無料の範囲で動きます。

## 3. LINE Developersでテスト用チャネルを作る

**まずは本番とは別の「テスト用」のLINE公式アカウントを作ります。** 本番のアカウントには、確認が終わるまで一切つなぎません。

> 2024年9月から、Messaging APIのチャネルは「LINE公式アカウントを作ってから、Messaging APIを有効にする」順番になりました。

### 3-1. テスト用のLINE公式アカウントを作る
1. https://entry.line.biz/start/jp/ を開き、「LINE公式アカウントをはじめる」から作成します。
2. アカウント名は、区別しやすいように **「せのりんか（テスト）」** などにします。
3. 業種などは本番と同じで構いません。作成が終わると「LINE Official Account Manager」（以下「管理画面」）が開きます。

### 3-2. Messaging APIを有効にする
1. 管理画面の右上「**設定**」→ 左メニュー「**Messaging API**」を開きます。
2. 「**Messaging APIを利用する**」を押します。
3. 開発者情報（名前・メールアドレス）を入力し、プロバイダーを作成します（名前は「せのりんか」など）。
4. プライバシーポリシー・利用規約のURLは空欄のままで構いません。
5. 完了すると「Channel ID」と「**Channel secret**」が表示されます。

### 3-3. Botに必要な2つの鍵をメモする
1. https://developers.line.biz/console/ を開き、LINEアカウントでログインします。
2. 作ったプロバイダー → 「せのりんか（テスト）」のチャネルを開きます。
3. 「**チャネル基本設定**」タブの一番下近くにある **チャネルシークレット** をコピーしてメモします。
4. 「**Messaging API設定**」タブの一番下にある **チャネルアクセストークン（長期）** の「発行」を押し、出てきた長い文字列をメモします。
5. 同じタブの上の方にある **QRコード** を、ご自分のスマホのLINEで読み取り、テスト用アカウントを友だち追加しておきます。

> この2つの鍵は「Botの合鍵」です。4-3で作るGoogleの鍵とあわせて、**3つの鍵を入れる場所は Render の設定画面（5章）の中だけ** です。
> 人に見せたり、SNS・GitHub・メール・AIとのチャット（Claude などを含む）に貼ったりしないでください。

## 4. Googleスプレッドシートを用意する

Botがスプレッドシートを読み書きできるように、**Bot専用のGoogleアカウント（サービスアカウント）** を作り、シートを共有します。

### 4-1. Google Cloudでプロジェクトを作る
1. https://console.cloud.google.com/ を開き、Googleアカウントでログインします（初回は利用規約に同意）。
2. 画面上部のプロジェクト選択 →「**新しいプロジェクト**」→ 名前「senorinka-line-bot」→「作成」。
3. 作ったプロジェクトが選ばれていることを確認します。

> クレジットカードの登録は不要です。

### 4-2. Google Sheets API を有効にする
1. 左上のメニュー（≡）→「**APIとサービス**」→「**ライブラリ**」。
2. 「Google Sheets API」を検索して開き、「**有効にする**」を押します。

### 4-3. サービスアカウントと鍵を作る
1. メニュー（≡）→「**IAMと管理**」→「**サービスアカウント**」→「**サービスアカウントを作成**」。
2. 名前に「line-bot」と入れて「作成して続行」。ロールなどは何も選ばずに「完了」で大丈夫です。
3. 一覧に出てきた `line-bot@○○○.iam.gserviceaccount.com` という**メールアドレスをメモ**します。
4. そのアカウントをクリック →「**鍵**」タブ →「鍵を追加」→「新しい鍵を作成」→「**JSON**」→「作成」。
5. JSONファイルがダウンロードされます。**これが3つ目の鍵です。** 大切に保管し、人に渡さないでください。

### 4-4. スプレッドシートを作って共有する
1. https://sheets.new を開いて、新しいスプレッドシートを作ります。名前は「せのりんかBot 文面」など。
2. 右上「**共有**」→ 4-3でメモした `line-bot@…iam.gserviceaccount.com` を入れ、権限を「**編集者**」にして送信します
   （「通知」のチェックは外して構いません）。
3. ブラウザのURLを見て、`https://docs.google.com/spreadsheets/d/` **ここの長い文字列** `/edit…` の部分を
   **スプレッドシートID** としてメモします。

> シートの中身は空のままで大丈夫です。Botが最初に起動したとき、必要なタブ（「設定」「文面」「おみくじ」「診断質問」「キーワード応答」「チェック結果」）と仮文を自動で書き込みます。
>
> このシートの「受付記録」タブには、お客さまのLINEのユーザーIDも保存されます。**共有はご本人とBot（サービスアカウント）だけ** にしてください。

## 5. Renderにデプロイする（Botを動かす）

### 5-1. Renderに登録
1. https://render.com/ を開き、「Get Started」→ **GitHubでログイン** します。
2. GitHubから「Renderにリポジトリを見せてよいか」と聞かれたら、`senorinka-posts` を許可します。

### 5-2. Botを作る
1. Renderの画面で「**New +**」→「**Blueprint**」を選びます。
2. リポジトリ `senorinka-posts` を選びます。
   - ブランチは、`line-bot` フォルダが入っているブランチを選んでください（`main` に取り込み済みなら `main`）。
3. Renderが `render.yaml` を読み取り、「senorinka-line-bot」というサービスを作ろうとします。
4. 環境変数（下の表）の入力欄が出るので、メモした値を貼り付けます。

| 環境変数の名前 | 入れる値 |
|---|---|
| `LINE_CHANNEL_SECRET` | 3-3 でメモしたチャネルシークレット |
| `LINE_CHANNEL_ACCESS_TOKEN` | 3-3 でメモしたチャネルアクセストークン（長期） |
| `SPREADSHEET_ID` | 4-4 でメモしたスプレッドシートID |
| `GOOGLE_SERVICE_ACCOUNT_JSON` | 4-3 でダウンロードしたJSONファイルを、メモ帳などで開いて**中身をまるごと**コピーしたもの |

5. 「**Apply**（適用）」を押すと、デプロイが始まります。数分待ち、画面に **Live** と出たら完了です。
6. 画面上部に表示される `https://senorinka-line-bot-xxxx.onrender.com` のような**URLをメモ**します。
7. 確認：ブラウザでそのURLの末尾に `/health` を付けて開き（例 `https://…onrender.com/health`）、`ok` と出ればBotは動いています。
8. スプレッドシートを開き直して、「設定」「文面」「おみくじ」「診断質問」「キーワード応答」「チェック結果」のタブができていればGoogleとの接続もOKです。

> 環境変数をあとで変えたいときは、Renderのサービス画面 →「**Environment**」で直して「Save Changes」。自動で再起動されます。

## 6. LINEとBotをつなぐ

### 6-1. Webhook URL を登録する
1. LINE Developers の「せのりんか（テスト）」チャネル →「**Messaging API設定**」タブ。
2. 「Webhook URL」の「編集」を押し、5-6のURLの末尾に `/callback` を付けて入力します。
   例：`https://senorinka-line-bot-xxxx.onrender.com/callback`
3. 「更新」→「**検証**」を押して「成功」と出ればOK。
   （失敗する場合は、先にブラウザで `/health` を開いてBotを起こしてから、もう一度「検証」を押してください）
4. すぐ下の「**Webhookの利用**」をオンにします。

### 6-2. 管理画面の応答設定
LINE Official Account Manager →「設定」→「**応答設定**」で、次のようにします。

| 項目 | 設定 | 理由 |
|---|---|---|
| チャット | オン | ご本人が1対1で返信できるように |
| Webhook | **オン** | Botを動かすため |
| 応答メッセージ | **オフ** | LINE標準の自動返信がBotの返信と重ならないように |
| あいさつメッセージ | **オフ** | 友だち追加のあいさつはBotが送るため（オンのままだと2通届きます） |

## 7. Botを眠らせない設定

Renderの無料プランは、**15分アクセスがないとBotが眠り**、次のメッセージで起きるまで30〜50秒かかります。
その間に返信が遅れたり、届かなかったりすることがあるので、無料の見回りサービスで定期的に起こしておきます。

1. https://cron-job.org/ に無料登録します。
2. 「CREATE CRONJOB」を押します。
3. Title：`senorinka-bot`、URL：`https://senorinka-line-bot-xxxx.onrender.com/health`（5-6のURL＋`/health`）。
4. 実行間隔（Execution schedule）を「**Every 10 minutes**」にして保存します。

> Renderの無料枠は月750時間で、Bot1つを24時間動かしても足ります（月最大744時間）。

## 8. 動作確認：月夜おみくじ

テスト用アカウントを友だち追加したスマホのLINEで、次のとおり送って確かめます。

| # | 送るもの | 期待する返事 |
|---|---|---|
| 1 | `おみくじ` | 「月夜おみくじへようこそ…」の仮文と、画面下に **1〜12のボタン** |
| 2 | ボタンの `9` を押す | `9番　ほどけ結` → 本文の仮文 → 診断への橋渡しの仮文 |
| 3 | もう一度 `おみくじ` → `9` | 2と**同じ結果**（番号ごとに結果は固定） |
| 4 | `おみくじ` → `１２`（全角）や `3番` | それぞれ `12番　朝結`、`3番　中結` |
| 5 | `おみくじ` → `13` | 「1〜12の番号で、もう一度…」と、ボタンが出直す |
| 6 | （おみくじを始めずに）`5` | **返信なし** |
| 7 | `こんにちは` | **返信なし**（ご本人が手で返す想定） |
| 8 | シートの「おみくじ」タブで1番の本文を書き換え → 5分待って `おみくじ` → `1` | 書き換えた文が出る |

全部そのとおりなら、機能1の確認は完了です。

> 「おみくじ」と送ってから**30分**以内に番号を送ってもらう決まりです。30分を過ぎてから数字だけ送られた場合は、
> 返信しません（もう一度「おみくじ」と送れば引き直せます）。

## 9. 動作確認：簡易・彼の本音診断

診断の受付は、**最初は「停止」になっています。** スイッチを入れるまで、受付は始まりません。

### 9-1. 準備（テスト用のシートで）
1. スプレッドシートの「**設定**」タブを開き、`診断の受付` の値を `受付中` に書き換えます。
2. 動作を確かめやすいように、`診断の受付上限` を一時的に `2` にしておきます。
3. 30秒ほど待ちます（スイッチと上限は、30秒以内に反映されます）。

### 9-2. 確認する流れ

| # | 送るもの | 期待する返事 |
|---|---|---|
| 1 | （スイッチを入れる前に）`診断` | 「ただいま診断の受付はお休みしています」の仮文。受付は始まらない |
| 2 | （スイッチを入れたあと）`診断` | 案内の仮文 → **質問①**（下に選択肢のボタン） |
| 3 | ボタンの `片思い` を押す | **質問②**（選択肢のボタン） |
| 4 | `1か月以内` を押す | **質問③**（ボタンなし。自由に入力） |
| 5 | 好きな文を送る | 「受付番号 **1番** で承りました」→「お返事は順番に…」の2通 |
| 6 | シートの「**受付記録**」タブを開く | 1行増えている（日時・受付番号・ユーザーID・回答1〜3） |
| 7 | もう一度 `診断` | 「**すでにお受けしています**」の仮文（同じ方は1回まで） |
| 8 | `診断` → `片思い` → `やめる` | 「中断しました」の仮文。記録は増えない |
| 9 | 別のLINEアカウント（ご家族のスマホなど）で最後まで答える | 「受付番号 **2番**」 |
| 10 | 3つ目のアカウントで `診断`（※ない場合は、「受付記録」の自分の行を削除し、上限を `1` にして30秒待ってから自分で `診断`） | 上限に達しているので「締め切りました」の仮文 |
| 11 | 診断の途中で `おみくじ` | おみくじが始まり、診断は取り消し |

> 1つのLINEアカウントで何度も試したいときは、「受付記録」タブの自分の行を削除すれば、また受付できるようになります。

### 9-3. 確認が終わったら（大事）
1. 「受付記録」タブの**テストの行をすべて削除**します（見出しの1行目は残す）。受付番号は、残っている番号の続きから振られるので、全部消せば次は1番からになります。
2. `診断の受付上限` を `20` に戻します。
3. `診断の受付` を `停止` に戻します（受付を始める日まで）。

## 10. 受付の操作（スイッチ・上限・記録）

すべて「**設定**」タブで操作します。変更は **30秒ほど** で反映されます。

| 項目（変えない） | 値 | 説明 |
|---|---|---|
| `診断の受付` | `受付中` または `停止` | `受付中` にすると受付を始めます。`停止` で止まります。受付を始める日に `受付中` にしてください |
| `診断の受付上限` | 数字（初期値 `20`） | 通算の受付件数の上限。「受付記録」タブの件数がこの数に達すると、締め切りの文を返します |
| `診断の中断キーワード` | 初期値 `やめる` | 診断の途中でこの言葉が送られたら中断します |

**受付上限を変えるには**：`診断の受付上限` の数字を書き換えるだけです（例：`20` → `25`）。
数字以外（「にじゅう」など）を入れると、受けすぎを防ぐため **締め切り扱い** になります。全角の `２０` は大丈夫です。

**受付が止まる条件**（どれか1つでも当てはまると止まります）
- `診断の受付` が `受付中` 以外のとき → 「受付停止中」の文
- その方がすでに「受付記録」にいるとき → 「受付済み」の文
- 「受付記録」の件数が上限に達したとき → 「締め切り」の文

上限ちょうどのタイミングで何人かが同時に答えていた場合も、**最後の質問に答えた時点で改めて確認する**ので、上限を超えて受け付けることはありません
（その方には締め切りの文が届きます）。

### 「受付記録」タブの見方
最初のお申し込みが来たときに、Botが自動で作ります。

| 列 | 中身 |
|---|---|
| 日時 | 受付した日時（日本時間） |
| 受付番号 | 1, 2, 3… |
| ユーザーID | LINEのユーザーID（`U` で始まる長い文字列）。お返事を送るときの照合用 |
| 回答1〜 | 質問の順番どおりの回答 |

- 行を並べ替えたり、右側に「メモ」「返信済み」などの列を足したりしても大丈夫です。**見出しの「受付番号」「ユーザーID」の文字は変えないでください。**
- **ユーザーIDは個人情報です。** シートの共有はご本人とBotだけにしてください。

### 「進行状況」タブ
診断の途中まで答えた方の内容を、Botが一時的に置いておく場所です（Botが再起動しても続きから答えられるように）。
**触らなくて大丈夫です。** 6時間たった途中経過は無効になり、その方の次のメッセージは診断の回答として扱われません。

## 11. 文面の差し替え方法

**文面はすべてスプレッドシートで直します。** 見出し（1行目）と、タブの名前は変えないでください。
直したあと、だいたい **5分以内** にLINEの返事に反映されます。

`【仮文】` と書いてあるところが、差し替えてほしい場所です。

### 「おみくじ」タブ（12種類の結果）

| 列 | 中身 | 直してよいか |
|---|---|---|
| 番号 | 1〜12 | **変えない**（番号と結果の組み合わせが固定のため） |
| 結果名 | 大結・結実・中結・小結・再結・月結・星結・待結・ほどけ結・新結・深結・朝結 | 直してOK |
| 本文 | 結果の文章 | 直してOK |
| 診断への橋渡し文 | 結果の最後に付く、無料診断へのご案内 | 直してOK。**空欄にすると何も付きません** |

番号と結果の対応（初期状態）：
1 大結／2 結実／3 中結／4 小結／5 再結／6 月結／7 星結／8 待結／9 ほどけ結／10 新結／11 深結／12 朝結

### 「診断質問」タブ

| 列 | 中身 |
|---|---|
| 順番 | 聞く順番（1, 2, 3…）。小さい順に聞きます |
| 質問文 | 質問の文章 |
| 選択肢 | `/` で区切るとボタンになります（例：`1週間以内/1か月以内/半年以内`）。**空欄なら自由入力**。ボタンは1つ20文字・13個まで |

- 選択肢がある質問でも、お客さまは自由に文字を打って答えることもできます（そのまま記録されます）。
- 行を足せば質問が増え、消せば減ります。質問文を空欄にした行は飛ばします。
- 初期の選択肢（「お付き合い中」「1週間以内」など）も仮のものです。自由に直してください。
- 受付を始めてから質問の数や順番を変えると、「受付記録」の回答1〜の意味がずれます。**受付期間中は変えない**のがおすすめです。

### 「文面」タブ

| キー（変えない） | いつ使われるか |
|---|---|
| `おみくじ_番号の案内` | 「おみくじ」と送られたとき（下に1〜12のボタンが付きます） |
| `おみくじ_番号が範囲外` | おみくじの途中で、1〜12以外の数字が送られたとき |
| `おみくじ_結果の見出し` | 結果の1行目。`{番号}` `{結果名}` は自動で置き換わります |
| `診断_はじめの案内` | 「診断」と送られ、受付できるとき。このあとに質問①が続きます（空欄にすると、いきなり質問①から） |
| `診断_受付完了` | 最後の質問に答え終わったとき。`{受付番号}` は自動で番号に置き換わります |
| `診断_返信の目安` | 受付完了のすぐあとに続けて送る文（例：順番に、数日以内にお返事します） |
| `診断_締め切り` | 受付上限に達しているとき |
| `診断_受付停止中` | `診断の受付` が `停止` のとき。**受付開始日を約束する言葉は入れないでください** |
| `診断_受付済み` | 同じ方から2回目のお申し込みがあったとき（「すでにお受けしています」） |
| `診断_中断` | 途中で「やめる」と送られたとき |
| `診断_エラー` | スプレッドシートに書き込めなかったときなど、Bot側の不調のとき |

| `あいさつ` | 友だち追加されたとき（ブロック解除されたときも）に送る文 |

### 「キーワード応答」タブ（キーワードの追加・変更）

お客さまが送った言葉に合わせて返す内容を、**1行に1つ** 書きます。行を足せばキーワードが増えます。

| 列 | 中身 |
|---|---|
| キーワード | 反応する言葉 |
| 一致方法 | `完全一致`（その言葉だけが送られたとき）／`含む`（文の中にその言葉が入っていたとき） |
| 返す文面 | 返す文章 |
| ボタン | 文章の下に出すボタン（`/` 区切り。例：`おみくじ/診断`）。空欄ならボタンなし |
| 動作 | `おみくじ` ＝月夜おみくじを始める／`診断` ＝診断の受付を始める／**空欄＝「返す文面」を返す** |

- 初期状態では、`おみくじ` と `診断` の2行（動作つき）と、例の `プロフィール` の行が入っています。例の行は消しても大丈夫です。
- 「おみくじ」「診断」の呼び名を変えたいときは、その行の **キーワード** を書き換えます（例：`おみくじ` → `月夜おみくじ`）。
  あわせて、あいさつのボタン（「設定」タブ）や、ボタンに書いた言葉も同じ言葉にそろえてください。
- 1つの動作に、キーワードを何行でも付けられます（例：`占い` という行を足して、動作を `おみくじ` にする）。
- 調べる順番：まず **完全一致** の行、なければ **含む** の行を上から順に見て、最初に当てはまった行を使います。
- **診断の途中の方**が送った言葉は、キーワードより **回答** として受け取ります（`おみくじ` `診断` にぴったり一致したときだけは、そちらを始めます）。
- どの行にも当てはまらない言葉には、Botは返信しません。ご本人がチャット画面からお返事ください。
- 「含む」は便利ですが、広く反応しすぎることがあります（例：`彼` を「含む」にすると、ほとんどの相談文に反応します）。迷ったら `完全一致` がおすすめです。

### 「設定」タブ

| 項目（変えない） | 値の意味 |
|---|---|
| `あいさつのボタン` | あいさつの下に出すボタン（`/` 区切り。初期値 `おみくじ/診断`）。出さないときは `なし` |
| `使わない言葉` | 文面に入っていたら「チェック結果」タブでお知らせする言葉（`/` 区切りで追加できます） |
| 診断関係の3項目 | 10章を見てください |

### 「チェック結果」タブ（表現チェック）
Botが文面を読み直すたびに、すべての文面に `使わない言葉`（初期値：必ず／絶対／今すぐ行動しないと）が入っていないか調べ、
結果をこのタブに書きます。**文面を直したら、5分ほどしてからこのタブを見てください。**
「問題は見つかりませんでした」と出ていればOKです。見つかった場合は、場所と言葉が書かれます
（お知らせするだけで、送信は止めません）。

### 書き方のコツ
- **セルの中で改行する**：Windowsは `Alt + Enter`、Macは `⌘ + Enter`（または `Option + Enter`）。
- 1つのメッセージは最長5,000文字です。
- 文面を空欄にすると、最初に入っていた仮文に戻ります（うっかり消しても、Botが無言になることはありません）。
- **表現のルール**：「必ず」「絶対」など結果や効果を断定する言葉、不安をあおる言葉、読む人を責める言葉は使わないでください。

## 13. 本番アカウントへの切り替え

**テスト用での確認（8・9・12章）がすべて終わり、ご本人がOKを出してから** 行います。
同じBot（Render）とスプレッドシートを、そのまま本番に付け替えます。

### 13-1. 本番の鍵を用意する
1. 本番の「せのりんか」のLINE公式アカウントで、3-2と同じ手順で **Messaging APIを有効** にします
   （有効にすると、管理画面の一部の設定が変わります。すでに使っている自動応答などがあれば、先にメモしておいてください）。
2. 3-3と同じ手順で、**本番の** チャネルシークレットとチャネルアクセストークン（長期）を用意します。
   入れる場所は、引き続き **Renderの設定画面の中だけ** です。

### 13-2. シートを本番用に整える
1. 9-3の片付け（受付記録のテスト行の削除、上限を `20` に、受付スイッチを `停止` に）が済んでいるか確認します。
2. 文面に `【仮文】` が残っていないか確認します（Ctrl+F／⌘+F で「仮文」を検索）。
3. 「チェック結果」タブが「問題は見つかりませんでした」になっているか確認します。

### 13-3. 付け替える
1. Renderのサービス画面 →「Environment」で、`LINE_CHANNEL_SECRET` と `LINE_CHANNEL_ACCESS_TOKEN` を **本番の値に書き換えて** 保存します（自動で再起動します）。
2. LINE Developersの **本番** チャネル →「Messaging API設定」で、Webhook URLに **テストと同じURL**（`https://…onrender.com/callback`）を入れて「検証」→「Webhookの利用」をオン。
3. **本番** の管理画面の「応答設定」を6-2の表と同じにします（Webhookオン・応答メッセージオフ・あいさつメッセージオフ・チャットオン）。
4. テスト用チャネルの「Webhookの利用」はオフにしておきます。
5. ご本人のスマホで本番アカウントに `おみくじ` と送り、返事が来ることを確認します。
   （診断は、受付スイッチを入れるまで「受付停止中」の文が返ります。これで正常です）

### 13-4. 受付を始める日
「設定」タブの `診断の受付` を `受付中` にするだけです（30秒ほどで反映）。

### 元に戻したいとき
Renderの2つの鍵をテスト用の値に戻し、本番チャネルの「Webhookの利用」をオフ、本番の管理画面の設定を元に戻せば、切り替え前の状態に戻ります。

## 14. 困ったとき

| 症状 | 確かめること |
|---|---|
| 何を送っても返事がない | ①`/health` を開いて `ok` が出るか（出なければRenderの画面で「Logs」を確認）②LINE Developersの「Webhookの利用」がオンか ③管理画面の応答設定で Webhook がオンか |
| 返事が `【仮文】` のまま | ①5分待ったか ②シートをサービスアカウントに「編集者」で共有しているか ③`SPREADSHEET_ID` が正しいか |
| 頼んでいない返事が来る・あいさつが2通届く | 管理画面の「応答メッセージ」「あいさつメッセージ」がオフになっているか |
| キーワードに反応しない | 「キーワード応答」タブの綴り・一致方法。5分待ったか。診断の途中だと回答として受け取られます（`やめる` で抜けられます） |
| 「検証」が失敗する | `/health` を開いてBotを起こしてから、もう一度押す。URLの末尾が `/callback` か確認 |
| 返事が遅い・たまに来ない | 7章の見回り設定が動いているか（cron-job.org の履歴） |
| 診断で「受付停止中」の文しか返らない | 「設定」タブの `診断の受付` が `受付中` になっているか。30秒待ったか |
| 診断で「締め切りました」が出る | 「受付記録」の件数が `診断の受付上限` に達していないか。上限欄に数字以外が入っていないか |
| 診断で「うまく進みませんでした」が出る | Googleとの接続の不調です。シートの共有設定（4-4）を確認し、RenderのLogsを見てください |

RenderのLogs画面に `文面の読み込みに失敗しました` と出ている場合は、Googleとの接続（4章）を見直してください。
その間も、Botは最後に読めた文面（または仮文）で動き続けます。

## 15. 開発者向けメモ

```
line-bot/
├── app.py                     Webサーバーの入口（/callback, /health）
├── bot/
│   ├── router.py              受け取った文字 → 返す文面 を決める（LINEに依存しない）
│   ├── content.py             文面・設定の読み込みとキャッシュ
│   ├── sheets.py              スプレッドシート接続・不足タブの自動作成
│   ├── records.py             診断の受付記録・進行状況の保存（シート／メモリ）
│   └── state.py               「おみくじの番号待ち」などの一時的な状態
├── content/default_content.json  仮文（シート未接続時・初期値・空欄時の代わり）
├── tools/simulate.py          LINEなしで会話を試す道具
├── tests/                     自動テスト
├── render.yaml                Renderの設定
└── requirements.txt
```

- 言語：Python 3.12 / Flask / line-bot-sdk v3 / gspread
- シートのタブ構成は `content/default_content.json` と同じです。新しい文面キーを足すときは、JSONに追加すれば、次の起動時にシートへ自動で追記されます（既存の行は上書きしません）。
- プロセスは1つ（`--workers 1`）で動かし、診断の処理はロックで1件ずつ行います。受付番号の重複と上限超えを防ぐためです。ワーカーを増やす場合は採番の仕組みを見直してください。
- シート未接続（`SPREADSHEET_ID` なし）のときは、受付記録・進行状況はメモリに置きます（再起動で消えます）。

ローカルでの確認：

```bash
cd line-bot
```

```bash
pip install -r requirements-dev.txt
```

```bash
python -m pytest -q
```

```bash
python tools/simulate.py --open
```

（`--open` を付けると、診断の受付を「受付中」にした状態で試せます。`/follow` と入力すると、友だち追加のあいさつを試せます）
